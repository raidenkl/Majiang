# 電脳麻将 ネット対戦サーバー

`netplay.html` クライアント(`src/js/netplay.js`)専用の対戦サーバー。
express + socket.io で構成し、`Majiang.Game`(@kobalab/majiang-core)を
権威エンジンとしてサーバー側で対局を進行する。

- クライアント(`src/`)は一切変更しない。既存のネット対戦画面がそのまま動く
- 空席は `Majiang.AI`(@kobalab/majiang-ai)が補う(1人でも対局可能)
- 持ち時間を過ぎた席はサーバーが最小限の応答(パス/ツモ切り)を代行する
- 手牌は各席個別のメッセージとして配信されるため、他席の手牌はネット上に流れない

## 起動方法

```sh
npm install
npm run build        # dist/ を作成(初回のみ)
npm run server       # http://localhost:3830/ で待ち受け
```

環境変数:

| 変数             | 既定            | 説明
|:-----------------|:----------------|:---------------------------------
| `PORT`           | `3830`          | リッスン番号
| `BASE_PATH`      | (なし)          | リバースプロキシでサブパスに置く場合の接頭辞
| `SESSION_SECRET` | 起動時乱数      | セッション署名鍵(再起動で無効化されてよいなら既定で可)

LAN 内の他の端末からは `http://<サーバーのIP>:3830/netplay.html` を開く。

## 対局の流れ

1. `netplay.html` を開くとログインフォームが出る(ニックネームのみのゲストログイン)
2. ニックネームを入力して「登録」→ 部屋番号を入力して入室
   - 新しい番号なら部屋を新規作成、入室した順に `user[0]` が部屋の主
   - 4 人で満員。同じ番号に再度入室すると再接続扱い
3. 部屋の主がルールと持ち時間を選んで「対局開始」
   - 4 人揃っていなくても開始でき、空席は AI が埋める
4. 対局終了後、全員部屋に戻る(部屋の主は続けて再戦できる)

対局中の切断は席がオフライン表示になり、サーバーが自動応答で局を進める。
同一ブラウザで再接続(再読み込み)すると盤面を復元して対局に復帰できる。
全員がオフラインになってから 60 秒で部屋は破棄される。

## 通信プロトコル(socket.io)

ソケットのパスは `${BASE_PATH}/server/socket.io/`。
クライアント実装は `src/js/netplay.js`。

| イベント | 方向 | ペイロード | 説明
|:---------|:-----|:-----------|:-----------------------------------------
| `HELLO`  | S→C  | `{uid, name}` または `null` | 接続時に送る。`null` ならログイン画面
| `ROOM`   | C→S  | `(room_no)` | 入室(なければ作成)
| `ROOM`   | C→S  | `(room_no, uid)` | 退室(自分の uid、部屋の主は他席も指名可)
| `ROOM`   | S→C  | `{room_no, user:[{uid, name, offline?}…]}` | 在席情報。`user[0]` が部屋の主
| `START`  | C→S  | `(room_no, rule, timer)` | 対局開始(部屋の主のみ)。`rule` は `Majiang.rule()` で正規化済みのオブジェクト、`timer` は秒の配列
| `START`  | S→C  | (なし) | クライアントを牌卓画面へ切替させる
| `GAME`   | S→C  | `{players:[bool×4]}` | player id 順の接続状態
| `GAME`   | S→C  | `{say:{name, l}}` | ツモ/立直などの音声・演出通知(`l` は席順)
| `GAME`   | S→C  | `{seq, timer:[limit, allowed], …}` | 席ごとの個別メッセージ(応答が必要)。最後のものは `jieju: <牌譜>` を伴う
| `GAME`   | S→C  | `{kaiju: {…, log}}` など `seq` なし | 一方向通知(開局・再接続時の棋譜再生、`kaigang` など)
| `GAME`   | C→S  | `{seq, hule?/daopai?/dapai?/gang?/fulou?}` | `seq` を付して応答。語彙外はパス扱い
| `END`    | S→C  | (なし) | 対局終了。直後の `ROOM` で全員部屋画面へ戻る
| `ERROR`  | S→C  | 文字列 | エラー表示

### 席と player id

エンジン(`Majiang.Game`)は各メッセージを席順 `l`(0-3)ではなく
player id(部屋のメンバー配列の添字)ごとに個別化して `players[id]` へ渡す。
サーバーはそれをそのまま各席のソケットへ転送する。
`say` の `l` のみ席順で、クライアントも席順として扱うため変換は不要。

### 持ち時間

`START` の `timer[0]` が 1 手あたりの持ち時間(秒)。
各 `seq` メッセージに `timer: [limit, allowed]` を添えるので、
クライアントはカウントダウンを表示し、期限が来ると既定の応答
(ツモ切り/パス)を自動送出する。サーバー側も `limit + 2 秒` の猶予ののち、
応答が無ければパス/ツモ切りを代行する(切断席の自動進行もこれで行う)。

## 既知の制限(v1)

- ログインはゲストのみ(Hatena / Google OAuth は未実装。ボタンは自動で隠れる)
- セッションはメモリ上にあるため、サーバーの再起動で再ログインが必要
- 対局中の再接続では、棋譜ログの再生による盤面復元のため
  直前の 1 手が画面に反映されないことがある(次の局で整う)
- ロビーによる自動マッチング、チャット、観戦は未実装

## テスト

```sh
npm test        # node --test server/test/
```

実サーバーを ephemeral port で起動し、socket.io-client で模擬クライアントを
接続して HELLO/ROOM/START/GAME/END の一連の流れ、AI 3 人との一局完走、
対局中の切断・再接続を検証する。
